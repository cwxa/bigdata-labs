# 实验二 · 关联规则挖掘：Apriori 与 FP-growth

在 1892 条稀疏长事务上从零实现 Apriori 与 FP-growth，比较两类算法的计算代价，并对挖掘出的关联规则做 bootstrap 稳健性评估。

## 1. 数据

`data/array_data.csv`：每行一条事务，逗号分隔的整数 item id（课程实验指导书附带，已脱敏）。

| 指标 | 数值 |
|---|---:|
| 事务数 | 1892 |
| 不同 item 数 | 1990 |
| item 总出现次数 | 22300 |
| 平均事务长度 | 11.79 |
| 最短 / 最长事务 | 5 / 86 |
| 出现率 ≥5% / ≥1% 的 item | 14 / 279 |

item 极度长尾：1990 个 item 里只有 14 个在 5% 以上的事务中出现。这正是 Apriori 候选爆炸的温床——长事务让「子集枚举」的代价沿着事务长度指数增长。

## 2. 算法实现要点

### `apriori.py`

1. **项集内部表示统一为 `tuple(sorted(items))`**：既可哈希当字典键，又让 k-1 项集的自连接（Apriori-gen）退化为一次按字典序的分组扫描。
2. **支持度口径**：`supp(X) = count(X) / |D|`，阈值换算为最小计数 `min_count = ceil(min_sup × |D|)`，避免浮点比较。
3. **支持度计数两种策略，按估算代价自动选择**：
   - `SUBSET`：逐事务枚举其全部 k-子集，只在候选哈希表里累加——稀疏、候选多时更快；
   - `SCAN`：遍历候选，逐事务判断是否包含——候选少、事务长时更快。
4. **规则方向严格遵循讲义定义**：`Conf(X ⇐ Y) = P(X|Y) = supp(XY)/supp(Y)`，即 **Y 为前件（条件）、X 为后件（结论）**。绝大多数第三方库的方向相反，混用会得出错误解读。

### `fp_growth.py`

FP-tree 构建（两遍扫描：先统计频次建 F-list，再按频次降序插入并共享前缀）+ 条件模式基递归挖掘，附带树结构自检（节点计数之和必须等于过滤后事务长度之和，用于早期发现插入逻辑的丢项/重项）。

## 5. 结果

| min_sup | 频繁项集 | 最大阶数 | Apriori (s) | FP-growth (s) | 加速比 |
|---:|---:|---:|---:|---:|---:|
| 2% | 96 | 2 | 0.0219 | 0.0140 | 1.57× |
| 1% | 335 | 3 | 0.0981 | 0.0349 | 2.81× |
| 0.5% | 1115 | 4 | 0.5087 | 0.0968 | 5.26× |
| 0.2% | 6524 | 7 | 3.9990 | 0.2299 | 17.39× |

**剪枝代价**：min_sup=0.2% 时第 2 层产生 1,149,886 个候选，最终仅 3356 个频繁，候选/结果 ≈ 343:1。Apriori 的时间几乎全部花在给注定被剪掉的候选项集计数上，这也解释了加速比随支持度降低而放大的现象。

**规则稳健性**（这是本实验最关键的方法论部分）：min_sup=0.5% 时最强规则 lift 达 50，但其绝对支持计数仅个位数到二十几。lift 在小样本下是剧烈波动的比值。对 1892 条事务做 200 次有放回重采样后：

- min_sup=1%：49 条规则中 **27 条**（55%）的置信度 90% 区间下界仍 ≥ 阈值 → 判为稳健；
- 最高 lift 规则 `{86}→{27}`：conf 0.92、lift 41.44，90% 区间 conf ∈ [0.840, 1.000]、lift ∈ [33.8, 55.6]，四个方向一致成立，属可信关联；
- 反向规则 `{27}→{86}`：conf 0.548，区间下界 0.432 < 0.5，**不稳健**。方向不对称是关联规则的常见陷阱——`A→B` 成立不代表 `B→A` 成立。

因此本项目不把全部高 lift 规则当作"强关联"结论输出，而是只在置信度下界通过筛选时才认定稳健。
